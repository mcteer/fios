# Validation and rollback guide

These steps qualify an exact model, runtime, checker and Studio pair. The comparable Qwen3 run and the reduced Qwen MoE probe have hardware evidence. Full-pack disposition is recorded in [tasks.md](tasks.md).

1. **Portable baseline on fios-core.** Run `make spec-check`, `make scheduling-test`, `make chat-test`, `make pair-test` and `make check`. After implementation, run the proposed `make moe-test` for recipe, catalog, role, race, telemetry and evidence negatives. Cover old ledgers and profiles, wrong/future/missing samples, and 100 races with regular chat.
2. **Disposable Mini rehearsal.** Run the proposed `make moe-acceptance` using synthetic Studio slots, an isolated catalog and UI, and run-owned temporary directories. Start with a healthy preview. Exercise browser selection, keyboard use, busy and cancelled jobs, stale receipts, service restart, restore, privacy and cleanup. Verify zero large weights and native large-model ranks on the Mini and original preview health after teardown.
3. **Hardware prerequisite.** Verify the exact 005 report for the comparable-model path, including the successful armed edge-b link-loss test with the patched watchdog, fresh transport proof and release review. Follow the [005 guide](../005-paired-studio-inference/quickstart.md). Halt before Studio staging if the evidence is missing, stale or failed.
4. **Authorize the architecture probe.** Freeze the suite and generation settings before observing candidate outputs. Review pinned metadata, licensing, tokenizer, expected tensor mapping and per-host peak/disk estimates. Require a current 005 basis and an allowlist of reduced probe files with digests and byte ceilings. Refuse known unsafe candidates. Stage only those files using the Studio downloader. Run the reviewed two-rank probe, including GLM indexer reuse above 2,048 tokens. Record both receipts and independent cleanup.
5. **Authorize full acquisition.** Match the successful cleaned probe to the pinned candidate, adapter and devices. On each Studio recheck fresh disk and memory against the full local pack, temporary copies, retained artifacts, uneven partitions, replicated layers, KV cache, prefill/load peaks and the host floor. Refuse the transfer on a failed or missing check. Test that presenting probe-only approval to the full downloader transfers zero full shards. On separate approval, stage the exact reviewed pack on each Studio, verify file digests, actual tensor keys, shapes and quantization before load, and remove run-owned partials on failure.
6. **Keep evaluation reproducible.** Pin temperature zero, template, tokenizer, thresholds and case IDs in the suite. Reserve both Studios for each job. Run the private coding, campaign and native fault fixtures first. Timing that requires an approved visible answer is collected in the browser rehearsal in step 9.
7. **Quality and cap.** Require all six fixed controls and both existing read-only SQL cases plus two independently authored held-out SQL cases with distinct input tables. Use the existing bounded, read-only evaluator. Require correct outputs on all fixture datasets. Run the full boundary with exactly 7,168 input tokens including template and 1,024 generated, plus one over-limit refusal. Have a reviewer blind to model/pack grade four held-out synthetic campaign briefs. Anchor the 1–5 rubric per dimension: 5 meets all supplied canon facts, has a coherent sequence of scenes, or supplies all requested playable hooks, respectively. A 4 permits one minor omission with no contradiction or loss of playability, a 3 needs a substantive edit, a 2 needs several, a 1 is unusable. Each brief must reach 4 on all three dimensions. The policy fixture suite must meet 004's mandatory allow/deny controls using the real pinned checker. Re-run failed cases only as a separately identified attempt; never replace the original result in a frozen run set.
8. **Transport, failure and recovery.** Confirm real matching model-payload RDMA on both ranks. Reject the TCP control using a bounded reference workload and the same evidence verifier. Inject setup-only, mixed and replayed evidence. Exercise real cancellation, loss of each rank, and a controlled physical link interruption on the candidate pair. Preserve the management route, restore the link and verify a fresh paired run. Check each reachable rank stops by 17 s, stale ranks receive no capacity, and each slot independently proves cleanup. Use a separate attempt per fault.
9. **Measure the actual private UI on the pair.** After native gates pass, give the disposable fixture principal rehearsal access for the frozen cases. Keep the production model choice unpublished. Through WebKit, submit one short control with fresh rank processes, then five consecutive short controls with fresh processes and recently read files. Label the initial file-cache state as observed or unknown. Each short control has at most 256 input and 32 output tokens. For each turn require reporter launch to first model text within 180 s and browser submission to a visible, policy-approved complete answer within 240 s. For the full-budget browser case in step 7 require at least 2 generated tokens/s after the first token and an approved visible answer within 900 s. Record per-phase memory, prefill and decode rates. For each of the seven turns, join both hardware receipts and the browser observation by candidate, suite, case, repetition, job and attempt. Each observer uses its own monotonic clock. Reject missing render, checker refusal, missing/replayed receipts, mismatched observations or a threshold breach. Capture a new suite version and repeat for any changed threshold.
10. **Release rehearsal and cleanup.** Exercise denial, withdrawal in flight, revision conflict, rollback, restart/restore and reopening fixture history. Close the fixture access. Record scrubbed build IDs, timings, per-rank margins, scores, cleanup and candidate dispositions. Only a complete report with the browser evidence permits separate production promotion. Retain only approved serving artifacts and verify preview health and active service ownership. Withdraw on drift and reactivate only a still-qualified revision after fencing and cleanup.


## Resource estimate commands

On fios-core, register the exact reviewed profile using `python3 -B -m backend.enroll --socket PATH large-model-register MANIFEST.json` with `PYTHONPATH=src`. Registration records the pair-only classification.

After the hardware prerequisite, the read-only `PYTHONPATH=src python3 -B tests/macos/moe_resources.py ABSOLUTE_STAGING_DIRECTORY` command yields one resource sample per Studio. The local admin can combine both samples under `observations`, provide per-Studio `budgets` with `disk_bytes` and `peak_bytes`, and supply the `candidate` and qualifying 005 `comparable` revision in a report. Use `large-model-resources REPORT.json` on the same operator socket. A successful resource estimate confers no download or launch authority.


Use `large-model-stage REPORT.json` on the operator socket to record a stage decision. Add the current job ledger `incarnation`, `stage` and the stage-specific evidence to the resource report. A probe report supplies `files`, a flat map from approved probe file names to `sha256` and `bytes`. Aggregate bytes are capped at 1 GiB. A full report supplies the cleaned `probe_job` and reviewed `pack_bytes` for that candidate. Query the current decision with `large-model-stage-check CANDIDATE APPROVAL probe|full`. The downloader and native worker bind the decision to its candidate, stage, current ledger and fresh observations.


For a reduced probe already acquired through the approved process, use `PYTHONPATH=src python3 -B tests/macos/stage_moe_probe.py SOURCE PRIVATE_STAGE_PARENT APPROVAL.json` on each Studio. Supply the current private probe approval from the Mini's operator socket. The helper checks local resources, writes only the approved files and publishes a run-owned directory after verifying hashes and sizes. Record each returned path for scoped teardown. The large worker's `large_stage` configuration must identify that stage and staged manifest digest. The controller supplies the same digest in its live grant.


For reviewed full-stage cases, pin the fixture and declare `review` as `coding` or `campaign` in the operator recipe. Reviewed fixtures have `expected: null` and a pinned synthetic prompt. After both ranks settle and clean up, the operator can pass the randomized ID to `large-review-page --blind ID --cursor 0` and use each returned cursor to read any remaining pages. Each response contains base64-encoded bytes and the output digest. Submit the grade through `large-review-verdict REPORT.json`, with the blind ID, digest and verdict. Coding uses a pass/fail result. Campaign review uses `canon_fidelity`, `narrative_clarity` and `session_usability` scores. The service retains the grade and digest and erases the raw sample.

Register the reviewed fixture digests with `large-model-suite SUITE.json` and use the returned revision in the profile's `evaluation` field. The suite hashes its fixed timing thresholds with the rubric, policy and case digests. Native recipes declare their frozen case. Timed browser fixtures are selected in order inside the rehearsal.

Run a configured native service with `--large-rehearsal`, a private browser bridge key and the fixed paired recipes. The service uses a temporary conversation store and the rehearsal owner. Before opening with `large-rehearsal-open REPORT.json`, run the real pinned checker controls through `large-policy-check REPORT.json` and collect the native case job IDs. Compile `tests/macos/check_moe_webkit.swift` in a temporary directory. Run it with the loopback chat URL and a private JSON request containing candidate, suite, case and prompt. After cleanup, submit its observation through `large-rehearsal-observe REPORT.json`. Submit the seven timed job IDs keyed by case through `large-rehearsal-record REPORT.json`. Close rehearsal access with `large-rehearsal-close`.

### Run the isolated hardware harness

1. On the Mini set `PYTHONPATH=src:tests:tests/macos`. Start `tests/macos/verify_long_policy.py --serving-record PATH` inside an owner-only run directory. Keep this checker alive through browser qualification. Use the exact revision from its record as `--policy`.
2. Run `tests/macos/prepare_moe_probe_inputs.py PRIVATE_INPUT_DIRECTORY POLICY_REVISION` to prepare the pinned pack manifest, reduced synthetic weights and frozen fixtures. The directory must be empty and owner-only.
3. Run `tests/macos/verify_moe_probe.py` with the comparable ledger, prepared manifests, probe directory, suite, checker revision and a new output ledger. Use `--keep-probe-environment PATH` to carry the exact Studio environments into full staging. This removes the reduced weights and temporary worker credentials after settling the probe. New installations can change package hashes because generated package records include the environment's installation path.
4. Run the same verifier with `--probe-ledger`, `--resume-stage` pointing at the retained probe environment, and `--stage-record` pointing at a new private receipt. Each shard needs new resource evidence. One Studio downloads the reviewed file and the other verifies its own copy over a temporary mutual TLS connection on the dedicated Thunderbolt link. The Mini coordinates and records the proof. Both independent model directories are verified before the stage receipt is written.
5. Resume with the full stage receipt, the exact same probe ledger, the checker record and a new output ledger. The harness prints the command for the administrator-assisted Thunderbolt interruption. It checks separately for each rank exit and restored paired generation. It exposes campaign drafts only on its local operator socket for blind scoring. After native and policy gates pass, the verifier runs the seven WebKit turns and closes the disposable browser service.
6. Release the checker by removing its record after qualification. Keep the scrubbed evidence and the pinned manifest. The isolated driver removes the scoped Studio staging directories on completion or failure. A stage receipt identifies any intentionally retained verified pack between steps 4 and 5.
