# Control plane contract v1

Local Unix IPC only; no native TCP listener. The development manager implements observation/operator sockets plus a separate task socket and the owner/stream payloads below. New task/inference/runtime admission remains disabled until reviewed enrollment/G2; this is not native activation evidence. The manager/supervisor run as the enrolled nonroot UID. Root is needed only for reviewed installation/ownership, not task processing.

## Identity and framing

Separate operator/task and read-only observation sockets,0700 parent/0600 sockets, verified peer credentials and role grants. Do not trust a `role` supplied in JSON. Optional SSH export runs a fixed installed `studioctl export` command on the observation socket using a dedicated forced-command key, `restrict`, no PTY/forwarding/agent forwarding/user environment/alternate command. Verify server host key; do not use the operator's general SSH identity in a container. Enrollment is separately reviewed; initial operation is local.

Every control request has version1, UUID request ID, fixed operation and strict payload. Length-prefixed UTF-8 JSON≤64KiB; duplicate keys/unknown fields/trailing bytes reject. Timeout2s for status,30s for control acknowledgement; a long lifecycle job returns a safe pending status rather than holding the RPC indefinitely. At most16 connected clients and4 outstanding commands/client; overload rejects before enqueue. Private manager↔Python frames use the separate worker contract. Task/sandbox payload transfer uses the bounded chunk protocol below, never an oversized control frame.

## Roles and operations

| Role | Operations | Never permitted |
| --- | --- | --- |
| Observer | `status`, `activity`, `resources` | Jobs, secrets, artifacts, lifecycle changes, arbitrary files/commands |
| Task client | `job.create`, `job.status`, `job.renew`, `job.cancel`, `artifact.read`, `model.request` for own grants | Other owners, force, native config or model selection outside approved mapping |
| Operator | Status plus `service.desired`, `service.drain`, `service.force`, `reconcile`, grant revocation | Arbitrary host shell, raw Docker arguments, inference-policy bypass |
| Sandbox | Its framed `model.request`, bounded output/export/completion | Any control socket or role selection; network/management/sibling access |

`job.create` accepts approved image digest/runner, bounded input manifest and declared finite resource/model grants. It never accepts host executable, Docker flags, mount path, raw endpoint or a new egress rule. Models cannot create jobs recursively. Local model-only platform jobs also have owner/lease/absolute lifetime and model budget; they consume dedicated slots (2/host) rather than sandbox slots (2/host), with4 total active/creating/reconciling jobs maximum. No unbounded idle-job or worker pool is permitted.

For task/sandbox input, `begin` declares job/stream identity, byte length/hash and type; `chunk` carries an increasing index and≤32KiB decoded data (base64 within a≤64KiB JSON frame); `end` verifies exact length/hash. At most1 incoming stream/job; cumulative input≤4MiB/job, model request text≤128000 UTF-16 within that input and the private1MiB command limit. Initial upload expires after10s without extension; reserve job capacity before buffering and never start a job or model POST before complete validation. Wrong/duplicate/missing/out-of-order chunks or timeout revoke the transfer and clean up reservation under the ordinary non-dispatch rules. Model/output frames toward a sandbox are split to≤8Ki UTF-16 and≤64KiB encoded frame, without splitting Unicode pairs. Artifacts use≤32KiB decoded chunks with≤16MiB cumulative/job and a30s transfer deadline; no chunk may reset a lease, request deadline or output budget. Partial content is ephemeral and not logged. Host control inputs cannot use this transfer protocol to smuggle additional operations.

## Implemented task payloads and owner data

`task.sock` fixes the task role at acceptance and authenticates the enrolled peer UID. Each task RPC (except global `status`) carries `owner`: a canonical base64 encoding of32 random bytes generated by the trusted native client. Persist only SHA256 of a domain-separated UID/token binding, never the token. Keep it outside sandbox/model inputs, argv, environment and logs. This protects sibling job grants at the protocol boundary, not a fully compromised same-user host that already controls native processes/runtime. The CLI `studioctl --state PRIVATE_DIRECTORY task` reads one strict≤64KiB version1 request from stdin with a2s read deadline, uses only `task.sock` and refuses management operations before connecting. Do not put credentials on its command line.

- `job.create` initial payload has exact keys `owner,phase="begin",idempotency,kind,length,sha256,lifetime,model,image,memory,cpus`. `kind` is `sandbox|model`; lifetime is milliseconds≤1800000. For model-only, image is null/memory and CPUs0; model must match trusted approved canonical mapping. For a sandbox, image must be an approved immutable digest and resources satisfy admission; model is an approved grant or null. The manager generates job UUID/creation nonce and binds sorted manifest hash to owner/idempotency before buffering input. Matching begin replay returns status only: no deadline reset, source reconstruction or execution replay.
- Continue with `job.create` payload `owner,phase="chunk",job,index,data` or `owner,phase="end",job`. Job UUID is also the sole initial input stream identity. Chunks are canonical base64≤32KiB decoded with zero-based increasing index. Complete length/hash/UTF-8/context validation precedes task input/start/model dispatch. `model.request` may carry chunk/end only for the owner's already-reserved model-only grant, never create/select a new job or access a sandbox/sibling grant.
- `job.status|job.renew|job.cancel` have exact payload `owner,job`. Status returns safe lifecycle state and independently retained unresolved-managed-request count. It may consume one ephemeral `event` (ordered event_index, opaque stdout/stderr base64 or typed model text/done). Output is at-most-once, never replayed after a lost reply/restart; four job mailboxes,64 events/1MiB queued per job,≤60000-byte event and fixed2s undrained backpressure. Overflow/expiry marks output_lost and revokes owned work rather than buffering indefinitely. Optional code_complete/exit_verified describe runner/container proof only, never native completion. Status reads do not renew any lease.
- `artifact.read` begin has exact payload `owner,phase="begin",artifact`. Owner/integrity-checked disk I/O runs off-loop and returns a generated finite stream handle/pending status. Next has `owner,phase="next",stream`, returning pending or ordered begin(length/hash)/chunk(index/base64)/end. Two total download handles;30s from begin, retention still applies, no seek/replay/revival after failure/end. Wrong owner cannot consume another stream. No filenames/paths are accepted.

`TaskCommands` is also exercised against real installed private model workers with a mock-only guard/HTTP endpoint. The installed manager uses no factory/runtime authority before enrollment: unavailable runtime results stay unknown and never prove absence. Source/profile loss closes admission without removing owner cancellation/status access. Artifact expiry/read/write/hash/fsync are serialized off-loop with two finite operation/result slots; progress is not a detached timer.

## Fixed local operator grammar

`studioctl --state PRIVATE_DIRECTORY service mlx|orbstack running|maintenance|stopped` sends only `service.desired` with exact string keys `service,desired` over `control.sock`. A successful durable intent reply includes `applied:false` until independently authorized execution is established; intent is not observed service state.

`service SERVICE drain` sends `service.drain` with exact `service`; `service SERVICE force prepare` sends `service.force` with exact `service,phase="prepare"`; `service SERVICE force confirm TOKEN SCOPE_DIGEST` sends exact `service,phase="confirm",token,scope_digest`. Token is canonical lowercase UUID, digest64 lowercase hex. Reject unknown services/actions, extra arguments/fields, coercions and malformed IDs before dispatch. No arbitrary argv/URLs/role/stdin selection. A submitted scope digest is only a comparison assertion, never affected-scope evidence or a grant. The manager must recompute trusted scope and enforce operator role/identity/maintenance/one-use30s rules before any future actuator. Current unenrolled drain/force calls return `native_unsupported`, `applied:false`, without minting confirmation or performing actions.

## Lifecycle and watchdog

- Exactly one manager authority per host/runtime. Persistent desired service state survives restart. Progress heartbeat every2s must attest control-loop progress, not a detached timer that stays healthy while the controller deadlocks.6s missing progress triggers manager TERM, then KILL/reap after1s additional grace; restart within30s subject to3 starts/10min and minimum10s spacing. Exhaustion → degraded, no more starts until window/explicit operator reset permits. The supervisor stays observable without session/runtime/model access.
- Session-dependent application actions are fixed identity-checked operations through the session adapter; no arbitrary executable/argv. Unavailable session/credentials produces `waiting_session`/`waiting_credentials`, not repeated privileged launch attempts.
- Service health must not invoke inference. Start an absent approved service only while desired running and ownership is verified. Do not start a duplicate native server alongside an existing app instance or adopt unknown processes.
- Drain denies new owned jobs/inference and waits up to60s. Active/uncertain external MLX work or unrelated containers cause refusal, not a forced timeout restart. Native terminal/quiescence proof required before ordinary MLX stop. OrbStack stop/restart requires all affected containers/machines accounted for; unmanaged or unknown work blocks automatic disruption.
- Force is an explicit operator operation containing a fresh affected-scope digest and single-use confirmation≤30s. Scope changes invalidate confirmation. Never synthesize operator approval from model text or an expired consent; record interruption/uncertainty accurately. Escalation must signal only verified process-start/executable identity, never PID alone.

## Errors and redaction

Fixed codes: `unauthorized`, `invalid_request`, `unsupported_version`, `busy`, `stale_observation`, `activity_unknown`, `native_unsupported`, `tracking_limit`, `resource_limit`, `lease_expired`, `job_conflict`, `image_unapproved`, `waiting_session`, `waiting_credentials`, `service_identity_changed`, `active_work`, `scope_changed`, `cleanup_pending`, `runtime_unavailable`, `model_unavailable`, `model_budget`, `model_failed`, `deadline`, `internal`.

Responses contain safe identity/state/counts and fixed codes, not raw native/CLI exceptions, prompts, filesystem listings or command output. Secrets stay in the host credential boundary and are not argv, routine logs, artifacts or sandbox environment. Inference-only credential access is limited to its supervised worker; Docker/SSH/operator credentials never enter Python.

### Readonly resource observations

The `resources` response carries `resource_observation.version=2`, the manager epoch/sequence, original host collection time, publication time and a fixed `signals` map. Signals are `physical_memory`, `available_memory`, `cpu`, `disk_free`, `pressure`, `thermal`, `low_power_mode`, `vm_available`, `gpu`, `gpu_in_use_memory` and `gpu_allocated_memory`. Each has `availability=observed|unknown|stale`, `sampled_at` and signed `age_ms`; absent/invalid timestamps and missing measurements stay null/unknown. Observed zero and false are valid measurements. Unknown driver support is unavailable/unknown, never a zero reading.

Host, GPU and VM use independent original collection times. Host/GPU times are taken before sensor work, so a delayed later read cannot refresh earlier observations. Five seconds of age and one second of future tolerance are inclusive; beyond those bounds values become null (or the explicit `unknown` pressure/thermal enum). VM capacity additionally requires its verified envelope epoch and original VM time; undated or unbound values are unknown. GPU counters report observed registry statistics, never idle, allocatable memory or native completion. Byte counters must fit the interoperable JSON integer range; nonfinite/out-of-range utilization and impossible available/physical combinations are unknown.

This export does not issue an admission lease or native/source capability. Existing admission independently applies critical measurement age, pressure/thermal/CPU/headroom/disk/VM checks and retained reservations. VM-dependent admission requires the VM measurement's own timestamp; a fresh host time never substitutes for a missing VM time. Host-only workers and the separate reviewed metadata bootstrap do not require a VM measurement. A consumer must bind the manager identity and validate epoch/sequence/time rather than refreshing cached data with its own timestamp. The public unenrolled manager continues reporting unknown VM capacity. Runtime/profile enrollment, all-VM architecture proof and installed resource/collector acceptance remain separate gates.

### Scoped service process census

`ServiceProcessCensus` is a read-only internal producer for a trusted executable and explicitly reviewed related bundle roots. It binds the current unprivileged UID, review digest and unchanged executable inode metadata. A capture checks a one-second monotonic elapsed budget between system calls and returns its original wall-clock timestamp. It must run off the manager loop; these checks cannot preempt a stalled kernel/filesystem call and are not a hard syscall deadline. Two bounded kernel UID PID lists must have the same membership; truncated, duplicate, incomplete or changing lists, failed process inspection, unexpected related helpers, multiple candidates, image replacement and clock rollback return unknown. A single candidate additionally requires matching effective/real/saved UID, kernel start token, exact canonical executable path and bounded no-follow FD hash verification. It never signals or starts a process and reads no arguments or environment.

`absent` means no matching process in this sampled UID/executable/bundle scope. It does not prove global service absence, exclude another UID or an unreviewed executable, reserve against a concurrent launch, attest loaded code, or establish native/GPU terminality. This producer is not connected to the public manager recovery issuer. Complete participant enrollment, duplicate-start exclusion and installed lifecycle acceptance remain required before automatic recovery can use it.
