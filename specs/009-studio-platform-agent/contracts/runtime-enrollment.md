# Runtime construction boundary — source implementation

`RuntimeEnrolledPolicy.load` constructs fixed runtime adapters only for the kernel-identified installed manager at `/Library/Application Support/Fios/Studio/bin/studio-manager`. Development, fixture and PR images return no policy before reading installation metadata. There is no task/operator JSON operation, environment override, alternate policy file, injectable file reader or public policy initializer.

The fixed policy is `/Library/Application Support/Fios/Studio/runtime-enrollment.json`. It must pass the existing descriptor-based root-owned/no-symlink/no-ACL/size/mode/stability reader. Its exact version2 schema contains `purpose: reviewed_platform_runtime`, positive nonroot `uid`, one of the two approved Studio `host` identities, canonical `state_path`, a direct `/Users/ACCOUNT` `home_path`, and lowercase SHA256 `review_sha256`, `manager_sha256`, `docker_sha256`, `orbctl_sha256`, `daemon_sha256`, plus a canonical `daemon_relative_path` under the fixed OrbStack bundle `Contents/` tree. Version1 cannot be silently upgraded into daemon authority and is refused. Duplicate/unknown/coerced/oversized fields refuse. UID, host and state must match the executing manager. The account home must be a real directory owned by that UID with no group/other write mode. The review hash names the operator's review receipt; neither it nor the decoded document is whole-repository/native provenance, source coverage or task admission proof.

The manager and Docker program must be reviewed root-owned, single-link immutable installation files. The Docker program has the fixed path `/Library/Application Support/Fios/Studio/bin/docker`, preserving its multicall basename without following the installed mutable Docker alias. Staging that binary, its dependency/provenance review and serialized stopped upgrades remain installer work; this factory does not copy or install it. Native OrbStack metadata uses the fixed `/Applications/OrbStack.app/Contents/MacOS/scli.app/Contents/MacOS/scli` path and independently pinned bytes. The complete OrbStack application tree must pass the bounded immutable-tree check before construction, so bundled dependencies/resources are not accepted from a writable tree. The factory checks current manager kernel PID/start/path and the reviewed current on-disk executable hashes; it does not attest mapped code or reconstruct dependency provenance. Immutable-path lifetime across later invocation still requires the reviewed installation and serialized upgrade discipline.

Docker uses only `--host unix://` plus the reviewed account home's fixed `/.orbstack/run/docker.sock` suffix. Neither inherited HOME nor Docker contexts select it. VM inventory/cap readers also receive that explicit reviewed home. The enrolled adapter captures a no-follow descriptor chain through root/account/private `.orbstack/run` directories, rejects permission-expanding ACLs and requires the exact same-UID single-link socket. Deny-only ACLs are permitted, preserving the normal account-home deny-delete ACL. Private runtime directories must be0700; socket group/other write is refused. Directory/leaf identity and permissions are rechecked around CLI operations under the original deadline; a changed endpoint is unavailable/uncertain even after local CLI success. Captured guards close only their own directory descriptors, never unlink or repair a socket. Metadata HTTP carries the same policy and checks it before request bytes and before accepting completion; attach preserves one original two-second monotonic handshake deadline through capture/connection/kernel peer verification (expired/future caller timestamps cannot restart that allowance), after which the connected descriptor binds that peer independently of pathname replacement. Kernel peer UID checks remain in both private APIs. Version2 additionally pins a root-reviewed daemon executable within the protected OrbStack application tree. PID is derived with `LOCAL_PEERPID` from the connected socket, never a packet/configured PID; real/effective/saved UID, kernel start, exact kernel path and bounded current file hash must match. CLI holds a passive no-request-byte connection across the command and revalidates its captured process identity after the effect. Metadata authenticates before request bytes and revalidates that captured process/start/image after EOF, when socket peer credentials may no longer be available. These are current process/on-disk image checks, not mapped-code, daemon VM epoch, native activity or terminality attestation. Same-user host compromise remains outside the sandbox isolation claim. Generic command execution rejects environment keys except a canonical absolute HOME and exact `DOCKER_CONFIG=/var/empty`, `DOCKER_CLI_HINTS=false`; child PATH and locale are fixed, with no inherited credentials, context or dynamic-library overrides. Fixed typed callers retain the existing two process slots, probe/action deadlines, identity-checked signals, finite output and exact-child reap/retention policy. CLI timeout remains unavailable/uncertain, never native terminality or proven non-dispatch.

Attach performs the image hash off-loop under the original handshake deadline. At most two actual authentications run, with no queue; cancelling/expiring the stream does not release an authentication slot until its worker finishes. The worker owns a duplicated close-on-exec FD, publishes one result and has no write callback. The serialized loop sends no HTTP/guest bytes until the result, private namespace and captured kernel identity are accepted. Afterward it checks process UID/start/path cheaply before polling the connected stream; current immutable-image lifetime remains an installer/serialized-upgrade prerequisite. Closing a stream cannot be undone by a late result and never clears inference ownership.

Construction performs no native CLI, daemon, container, application or model operation. The public manager composition still does not enable this runtime executor. Native compatibility/absence, authoritative activity/admission, approved images, resource/lease/ownership and installed acceptance must be completed independently before execution can be wired. No policy or executable was installed by the source fixtures. T009 integration and T049/T051 remain open; parser/development-refusal tests are not installed acceptance.

`node scripts/check-platform.mjs --mock --mutate-runtime-postcheck` compiles a private copy that replaces only the CLI postcheck with a descriptor-lifetime hold. Its expected runtime failure is `Successful local command hid a changed runtime endpoint`; compiler failures are not that evidence. The production source is never rewritten. The finite runner-owned fake CLI only renames a generated `/private/tmp/fios009-endpoint-UUID/.orbstack/run/docker.sock` and creates its own test symlink; no real runtime API is selected. Ordinary mock Debug/optimized suites compile/run the genuine postcheck.

## Resource-only profile construction

`VMResourceEnrolledPolicy` is an installed-only source factory, not public startup wiring or an installed profile. It first requires the existing opaque runtime enrollment and fixed kernel-identified manager. Its fixed root-protected `resource-enrollment.json` has exact fields: `version=1`, `purpose=reviewed_vm_resource_observation`, `architecture_contract=orbstack-shared-kernel-2.2.5`, `runtime_policy_sha256`, `orbstack_info_sha256`, `review_sha256` and one to eight unique immutable `metadata_images`. Unknown command/path/socket/environment/task/native-coverage fields reject. The Info.plist bytes, bundle identifier `dev.kdrag0n.MacVirt` and version2.2.5 are independently checked; another runtime policy or app version cannot borrow the review. Pure document/context validation returns no capability.

The private factory exposes only a fixed metadata reader for already-owned, hardened targets. Its image list is not a task-image grant. Construction sends no daemon or native CLI request and creates/starts nothing. The first kernel epoch comes from the authenticated owned-target reader; the exact first sample is reused once without another exec or timestamp refresh. The existing shared-kernel reader independently obtains the configured cap and binds profile/review/kernel/cap/physical identity. An inner instance is retained even after its first cap failure; later input cannot reset its epoch or clock fences. Verified-absence callbacks forward only to target metadata bookkeeping, never wait for source I/O, never clear global epoch/clock fences and never imply native inference terminality.

This profile grants no bootstrap creation, ordinary task execution, model admission or native lifecycle authority. The existing finite explicit bootstrap's ownership/lease/one-use/no-replay rules remain unchanged. Public manager composition, trusted running-service/owned-target prerequisites and no-implicit-start behavior still require integration/acceptance before enabling a real collector. Positive installed-manager/root-policy branches are unexecuted; no root policy is created by source tests. Current-file/bundle protection is inherited from runtime enrollment, not promoted into mapped-code or whole-native provenance attestation. Installed rollout remains separately gated.
