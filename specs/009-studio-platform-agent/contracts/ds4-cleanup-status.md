# DS4 checked cleanup in backend status

The checked-wrapper cleanup latch is independent sticky host uncertainty. The source guard already reads it, but the separate current-ABI backend collector previously read only the DS4 C host bitmask. After a checked cleanup refusal with C host/GPU flags0, that collector could report both DS4 fields false.

The current collector now ORs the existing shared checked-cleanup latch into `ds4_host_uncertain` when the reviewed DS4 source option is selected. Its GPU field remains independent. Availability bits, fixed64-byte FIF9 version2 encoding, timestamp/instance binding, reserved bytes and legacy protocol paths are unchanged. Unselected source still returns unavailable, even though the helper module exists. No bit is a native terminal, idle or admission proof; reading it neither clears uncertainty nor takes a management action.

The source fixture runs the actual collector and protocol encoder with explicit C substitutes and a local tracker. A checked session destruction refusal must set only the host value bit, even while both C negative getters return0. Separate controls retain C host errors, keep GPU errors in their own field, and link the unselected case without any DS4 C exports. The original collector must fail the encoded host-bit assertion before the candidate passes, in Debug and ReleaseSafe. These CPU component checks are separate from enclosing build/runtime receipts and installed/native acceptance.

Whole T020 and the other pending native/lifecycle tasks remain open. This change instruments existing MLX-Serve status; it adds no inference engine or model policy.
