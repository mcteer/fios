# Authoritative activity and future008 consumer contract v2

## Required source capability (G2)

The installed native serving boundary must supply trustworthy, coherent observations covering **every enabled inference path and client**, including direct native, LAN-tunnelled and manager requests. Count or conservatively represent ingress/preparation/loading, queued work, compute and response delivery. Include server instance identity, monotonic sequence/sample age, model identity/ownership and transitional/unknown state. No prompt/result/client-private content is required or exported.

Sampled scheduler gauges, multiple independent catalog/metrics GETs, loaded flags, process liveness, GPU utilization and manager ledgers are not by themselves sufficient. Existing26.10.3 source is candidate research, not an attested source satisfying this contract. Source-only native integration/testing is already authorized. Native installation/activation, privileged/disruptive acceptance and real inference remain separately gated; never scrape denied LAN routes or inject into the server.

Native protection must prevent different-model work from evicting/invalidating active ownership across snapshot→dispatch races, including work from bypass clients. It must cover queued/preparing/stream-delivery ownership, not only a decoding GPU slot. Additional same-model requests may share a resident model within native capacity. Native on-demand loading may replace an idle resident model. A loaded-only option is not required. The native boundary must reject or safely defer a different-model request while conflicting active ownership remains, without displacing it. A catalog recheck is advisory, not an atomic lease.

## Export

A version2 observation≤64KiB contains host, enrolled endpoint SHA256, manager epoch/sequence, native instance/sequence, sampled UTCms, source age, coverage `all_clients|unknown|unsupported`, resident exact identity or null, bounded per-model activity counts, preparation/transition flags, resources/service state and fixed safe reason. Per-model list≤64 entries, each counter0..2147483647; overflow or contradictory counts yields unknown rather than truncating to an idle-looking view. Multiple residents invalidate the configured single-model host.

Poll/sample every2s. Consumer rejects observations>5s old,>1s future, wrong host/endpoint/profile/native generation, repeated/regressing sequence after reconnect, unknown schema, missing fields or invalid numbers. A signed/authenticated transport does not excuse stale data. On reconnect/restart, obtain fresh epoch evidence before accepting sequence resets; never revive a cached idle snapshot.

`idle` requires all-client coverage, coherent absence of ingress/loading/queue/active/response ownership, no transitional native state and no unresolved local ownership incompatible with that proof. Unknown coverage is explicit and cannot pass SC-002/008. Busy attribution may be withheld if model identity is unknown; such a host is ineligible for conflicting requests.

### Source coherence implementation checkpoint

`NativeActivityCoherence` is an internal pure source-adapter component, not a new wire schema or an installed adapter. It accepts five disjoint ownership phases (ingress, preparation, queue, compute, response), global totals, unattributed counts, up to64 exact-byte model entries and a transition flag. Every count and the aggregate ownership sum must fit0..2147483647. Totals must exactly equal per-model plus unattributed counts; repeated byte identities, malformed IDs, more than one resident, conflicting busy/resident models, multiple busy models, transitions or unattributed ownership produce unknown with no exported ownership number. Unknown is never presented as zero. Preparation/ingress takes precedence over active/response, which takes precedence over queued; slow-reader response ownership remains active. These counts require a coherent source capture; the normalizer does not make separately sampled counters coherent.

Effective coverage is bounded by an independently reviewed code-only source ceiling. A frame's `all_clients` claim cannot raise unknown/unsupported source coverage. No production source ceiling is issued by these source checks.

### Version2 wire format and consumer

The raw observation has exactly these fields: `version`, `host`, `endpoint_hash`, `profile_hash`, `manager_epoch`, `native_epoch`, `sequence`, `sampled_at`, `native_sequence`, `native_sampled_at`, `source_age_ms`, `coverage`, `activity`, `resident_model`, `outstanding_owners`, `loading`, `transitioning`, `counts`, `unattributed_counts`, `models`, `reason`, `resources`, `services`, `local_ownership`. Control and private-worker protocols retain their existing versions; this version change applies only to the readonly observation.

`sequence`/`sampled_at` describe the manager's2s observation cadence. Native sequence/time are a pair of positive safe integer sequence and UTCms time, or both null when no native capture is available. Source age must exactly equal manager sample time minus native sample time; native time may be at most1s ahead of manager capture. The consumer independently rejects manager/native/resource samples>5s old or>1s future. It requires strictly advancing manager and native sequences, nonregressing sample times, exact independently enrolled host/endpoint/profile/manager/native identity, and sticky identity/clock fences. An unknown gap does not reset the last native sequence/time. Native generations are compared by exact UTF-8 bytes. None of this enrolls a generation from returned data.

Each counts object has exactly `ingress`, `preparing`, `queued`, `active`, `responding`; models≤64 entries contain exactly `model`, `resident`, `counts`. Known activity is derived from coherent totals/per-model/unattributed counts and single-residency policy; the consumer recomputes the activity, owner total, preparation flag and actual resident identity. Preparing/queued work does not itself claim residency. All counters and total ownership fit0..2147483647. Unknown exports have null counters/loading/residency/transition fields and an empty model list, never idle-looking zeroes. `reason` is one of `none`, `source_unknown`, `source_unsupported`, `source_unavailable`, `incoherent`, `local_ownership`, `observation_too_large`; arbitrary diagnostics or workload text reject.

`resources` is a diagnostic summary with exactly `sampled_at`, `pressure`, `thermal`; a null time requires both states unknown. It is not a VM/native capacity envelope. `services` contains exactly `mlx` and `orbstack` observed-state enum values. Neither resource pressure nor service readiness supplies native activity/admission authority. `local_ownership` contains exactly `unresolved_count`≤32, `uncertain` and `blocked`. Trusted local owners block idle/pre-dispatch gaps, uncertain ownership and different-model conflicts; known compatible same-model busy work remains eligible as advisory evidence. Invalid local tracking yields null count/uncertainty with blocked true. The consumer rejects impossible idle/unresolved or uncertain/unblocked claims. No observation clears the durable ledger.

The producer reserves512bytes for the fixed control envelope, limiting the raw frame to65024bytes. Oversize output becomes a small unknown observation with `observation_too_large`, without truncating model/count evidence into an idle-looking view. The SSH CLI structurally validates raw output and keeps stdout≤64KiB. Legacy compact version1 is accepted only for `unknown|unsupported` diagnostics with its exact old shape; a version1 all-client claim rejects. This compatibility path cannot supply the missing detailed evidence. The public manager currently emits version2 with native coverage unsupported and explicit null native capture metadata; genuine source integration/G2 and native admission remain unfinished. ## Owned requests and reconciliation

Before every actual manager-originated model POST persist one `(job_id,attempt)` record. Release it only on correlated native terminal proof, fully processed correlated response with completion evidence, proven non-dispatch, or authoritative same-instance quiescence including ingress/queued work. Disconnect, cancellation, worker exit, process restart, residency or elapsed time alone do not prove native completion. Completing a newer request never clears an older uncertain row.

Server epoch change invalidates old snapshots. Establish old process termination and absence of surviving compute/children before declaring its ownership quiescent; new health alone is not enough. If proof cannot be obtained, retain uncertain ownership and block conflicts. Native external clients are covered by the source, not forged into the manager-owned ledger.

### Durable scope implementation checkpoint

Development journal schema8 adds `inference_scopes`, keyed by `(job,attempt)`, in the same transaction as inference reservation and nonrefundable request history. The broker stores host, endpoint/profile hashes, manager/native epochs, exact canonical/native IDs, native sequence and native sample time; no URL, guard path, credential or workload body is retained. Scope JSON is bounded16KiB (including escaping of both maximum-length model IDs), rejects duplicate/unknown fields, noninteger/coerced sequence/time and invalid identities. All request-history entries require an explicit metadata row; low-level unbound fixtures use a literal null marker, so deleting a bound scope cannot silently turn it into an unbound claim. Public unbound fixture completion refuses bound/missing metadata.

Before the first worker permission byte, the parent durably changes reserved→dispatched. This is conservative possible-dispatch state, not actual-POST accounting. Restart changes unresolved reserved/dispatched entries to uncertain; it preserves the original scope and terminal history. The private worker resolves only its captured original scope after validated correlated response completion, or after a correlated terminal zero-POST summary plus complete child reaping. A mismatched generation/model/scope, duplicate terminal result or nonterminal outcome refuses. Successful completion cannot release another request. Terminal scope/outcome metadata remains until eligible job tombstone pruning; native ownership is never expired by that pruning.

Scope matching is necessary correlation, not independently sufficient native terminal evidence. No external native quiescence/process-epoch terminal issuer, atomic native admission or installed migration is supplied by this checkpoint. Ordinary startup/restore refuses schema7 unchanged; the explicit stopped-backup copy migrator validates known schema7, preserves unresolved ownership/budgets and publishes held schema8 without starting a controller. Backup format3 preserves that hold and opaque service-recovery bytes. It does not recover unknown native identity, activate an adapter or downgrade evolved state. Rollback retains and uses the original schema7 state/backup/artifact. T021 remains incomplete; T050 artifact rehearsal evidence is tracked separately.
