# Protected sandbox image/runtime composition

This is an internal source factory following the existing runtime/resource enrollment pattern. No policy is installed and public startup does not call it. Image approval, installed policy review, complete release review and positive installed acceptance remain independently gated. Decoded metadata cannot construct the opaque installed policy.

The only image-policy path is `/Library/Application Support/Fios/Studio/sandbox-enrollment.json`. Its strict4KiB version1 document has exactly `version`, `purpose` (`reviewed_platform_sandbox_images`), `runtime_policy_sha256`, `review_sha256` and `images`. The image list contains one to eight unique exact lowercase `sha256:` image IDs. No registry tag, executable, socket, environment, host mount, endpoint, native coverage or admission field is accepted. Hashes bind reviewed data; a review hash alone is not an approval token.

`SandboxEnrolledPolicy.load` first requires the existing opaque runtime factory, which checks the actual fixed installed manager and root-protected runtime/application/daemon inputs plus Studio/account/state context. Development/PR images return unconfigured before this image policy is read. The protected image document must bind that exact runtime-policy digest. Loading creates no subprocess, daemon request, container, image import/pull or model operation.

Separate off-loop `makeExecutor` rereads the unchanged protected image policy and reloads the installed runtime and resource policies. Resource enrollment must bind the same runtime-policy digest and cover every selected task image in its metadata image set. A separately reloaded resource/runtime generation cannot silently substitute for the original image-policy binding. The existing hardened `SandboxExecutor` and fixed resource reader are only constructed here; their constructors send no runtime requests. Effects remain in the existing bounded executor after trusted task admission, durable ownership, lease/resource accounting and channel validation.

This source composition does not issue native compatibility/capacity/reservation proof, supply task admission, enable public execution startup, write root policy, install services or authorize lifecycle changes. It does not turn the retained unapproved development image into an approved image. Installed positive policy/executor paths, complete immutable update custody, native integration and Studio operational acceptance are unproven. Root-policy/source observations are not atomic mapped-runtime or whole-native/OS provenance. Policy updates still require the separately reviewed stopped-process/backup/serialized-installation procedure.
