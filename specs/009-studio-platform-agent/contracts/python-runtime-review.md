# Python runtime byte-tree review

`PythonRuntimeTreeReview` consumes the existing version1 private Python candidate manifest. It returns byte observations only, without executing candidate code, constructing an enrolled policy or issuing inference/admission/installation authority. The manifest's producer/probe/distribution metadata is not a publisher or runtime-competence attestation. Independent factory metadata checks and reviewed installed configuration remain required.

Both entry points bind the expected manifest SHA256, exact declared relative UTF-8 file paths, file hashes/lengths/modes and the complete named tree, including the manifest itself. Reads use descriptor-relative no-follow operations, regular/single-link file checks, owner/ACL validation, stable per-file and directory identities, bounded recursion and32KiB streaming hashes. Unlisted files/directories and changed bytes refuse. Bounds are4MiB manifest,10000 declared files,128MiB per file,512MiB declared total,32 path components and120s cooperative review. Filesystem syscalls are not preempted.

`privateCandidate` requires the invoking unprivileged owner's private0700 tree and returns `rootProtected:false`. `rootProtectedCandidate` first applies the existing root-owned protected-ancestor/physical-tree gate (10s/8192-node ceiling), then checks root-owned declared bytes. This stricter root ceiling may refuse a larger otherwise valid development candidate. Private review cannot satisfy that root gate. Neither result is an enrollment capability or atomic mapped-runtime/whole-OS proof. Root-owned installation updates must remain serialized with stopped processes under the separately reviewed installer workflow.

`scripts/check-platform-worker-runtime.mjs` now performs the native byte review before its existing actual Swift factory/copied-interpreter metadata check. Compilation is bounded to two jobs; Python byte checks run before/after. Its network-denied process has a finite145s outer bound for the120s review plus fixed metadata operation/cleanup. No model binding or POST is created. Source/fixture tests and a genuine copied runtime are separate from positive installed root ownership, production policy issuance and Studio acceptance.
