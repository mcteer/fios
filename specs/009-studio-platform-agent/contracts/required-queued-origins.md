# Required queued worker origins

The private current-source load, ANE-build and unload handlers previously accepted a nil queue origin even when the target entry opted into ownership tracking. That allowed their worker prefixes to reach native work without the original scope. A later SDK rejection is too late to protect earlier backend or cleanup stages.

The candidate adds `Scope.retainRequest(io, origin, required)` to the existing queue-custody helper. Present origins follow the same bounded clone/validation path. A missing required origin fences the existing source tracker and returns `InvalidQueuedOrigins` before effects or sender acknowledgement. No replacement root is manufactured. The three handlers select `required` from the entry's existing compiled-source ownership opt-in and use their existing failure/completion paths. ANE's existing deferred build-counter decrement still runs on refusal.

Unenrolled callers retain their optional-origin behavior. An opted-in internal maintenance caller without origins now refuses too; this change does not establish that every such caller supplies custody. Full maintenance attribution, all-client coverage and native admission remain unfinished. The candidate cannot be activated on the strength of these fixtures. No model-selection algorithm, numerical engine, public ABI, routing or resource policy changes.
