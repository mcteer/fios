# Original ingress custody for unload

An unload caller may already have a retained ingress token without a model association. The producer previously treated that as fully attributed, so the worker and registered callbacks retained the original request but could not identify the cleanup model. This differs from an unparented idle operation: the original ingress token/correlation must be preserved.

The producer now validates its existing exact mutation for both cases. For a single unbound ingress, `bindMutationIngress` associates the reserved exact target under the tracker mutex without allocating/replacing a root, changing its correlation or reference count. Existing model-bound origins remain unchanged. Ambiguous unbound groups, invalid/duplicate/stale tokens, wrong mutation/model and prior uncertainty refuse before association. Other tracked owners cause ordinary `ModelOwned` refusal. Existing pre-pause ingress may continue; new unparented root allocation still obeys pause. Pause sequence and root-allocation sequence are independent and are never compared.

The shared mutation validator preserves prior unparented constructor semantics. Queue publication remains after source association, and checked unpublished rollback is unchanged. The binding is metadata ownership, not mutation/admission permission, native idle or terminal proof. Source diagnostic guard/coverage and all installed activation gates remain unchanged. No numerical engine, model policy, public ABI or wire format changes.

The metadata checker executes the actual producer and native tracker/queue scopes with explicit CPU registry/queue/completion substitutes. It expects6 original association failures,4 original controls and22 candidate passes in Debug/ReleaseSafe. Cases retain the original token/correlation, preserve an existing primary, refuse competing work and preserve pre-pause ingress. Additional candidate-only guards cover invalid origins and uncertainty; the unparented path is an explicit regression control. Initial driver-path setup failure and the corrected cross-counter implementation failure are retained as failures, not claimed product baselines.

The SDK checker executes the same original-ingress producer/native hooks with a selected genuine four-overlay SDK. Its registry/queue/completion are explicit CPU substitutes. Both candidate modes preserve the original token, correlation and exact model after producer/caller scope retirement through2 genuine CPU callbacks, including a destructor-enqueued child. Original modes fail model association; their callback count is unknown in the receipt. Counts are recorded only for a completed expected candidate sequence. No models, Metal buffers, device faults, native admission, installed identity or Studio acceptance are supplied.
