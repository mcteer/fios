# Configured distributed mode is independent negative evidence

The current CLI can enter distributed startup before HTTP ownership tracking is
initialized. Its exposed peer pointer is not a synchronized observation API.
The platform must not infer that those actors are absent from local HTTP counts.

This source increment adds a process-wide sticky marker at the existing `worker`,
`dist-probe` and `--dist` CLI branches, before their existing calls/validation.
The existing HTTP fixed negative getter reads that marker before its unchanged
ANE/SDK/DS4 composition. Public tracker preparation probes therefore fence and
refuse when the mode is configured. A new tracker epoch, reported ANE success,
local owner release or joined marker threads cannot clear it. Callback-free
snapshots do not independently refresh probes. A false marker is not evidence
of native idle, terminality or complete coverage.

RDMA implementation, argument, setting, operation, traffic, model policy or
numerical engine changes. The actual serving primary guard remains false;
this neither enables distributed admission nor establishes ownership of its
actors. All-client source/native proof and installed acceptance remain open.
