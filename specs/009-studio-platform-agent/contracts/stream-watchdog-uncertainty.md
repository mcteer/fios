# Streamed event watchdog uncertainty

An event watchdog deadline can expose a satisfied prefix while required reads are still nonterminal. That forced signal is not successful data production or native terminality. Latch the existing independent streamed-pool uncertainty before marking the gate forced and before making the prefix visible. Keep the original event-release policy; add no numerical implementation, model selection, native capability or activation.

The existing fixed negative bridge then closes subsequent native work/cleanup decisions. Returning from the local watchdog loop or observing its host event must not clear this independent flag or permit pool storage release.

The CPU-only regression runs the actual C watchdog and host-event signaling path with synthetic missing, empty, satisfied and already-stopped states. Only the final parked condition wait is replaced to end the local loop. A mutex-unlock witness checks the flag before event visibility; unexpected Metal signaling aborts. Original missing-data deadline behavior fails this witness; ordinary controls remain unchanged. This is not physical IO/device/native terminal proof.

The development checker requires explicit `--watchdog` selection and reconstructs the prior19-path pool patch before the new C overlay. The unselected source is refused before compilation. The default pool mode retains its strict source selection. Neither mode grants enrollment, model-plan, installation or runtime authority; all-client/installed acceptance remains open.
