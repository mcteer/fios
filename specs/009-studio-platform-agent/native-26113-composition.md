## Split SDK modes

1. **Stock SDK.** No private SDK/ANE/DS4 flags. This provides an ordinary build/control, not complete instrumentation.
2. **Four-overlay SDK.** Replay `mlx-c69303b-owner-uncertainty.patch`, `mlx-c69303b-metal-callback-fence.patch`, `mlx-c69303b-metal-callback-status.patch`, and `mlx-c69303b-owner-capture-refusal.patch` in that order on pristine MLX. A private server may select `-Dfios-source-sdk=true -Dfios-source-ane=true -Dfios-source-ds4=true` with the reviewed DS4 source root and a `-fios-source-fixture` version suffix. This is not the strict background-start seal. The default background refresh can still start.
3. **Participant-seal SDK.** Apply cumulative `mlx-c69303b-participant-seal.patch` to a *separate pristine* MLX tree. It is not a fifth overlay on the four-overlay SDK. For the strict private service add `-Dfios-source-background-seal=true`, which requires the genuine source SDK flag and applies equally to the executable and its unit-test bridge. Missing or refused seal fails the private constructor. Use matching compiled headers/library, not the previous SDK outputs. Do not change refresh in any installed process. For the private fixture only, the main child uses refresh `0` and the default child uses the unmodified setting to demonstrate refusal.

Both private service scopes use `-Dmas=true -Dversion=26.11.3-fios-source-fixture` and exact prepared `-Dwebp-prefix` and `-Dfios-ds4-source-root`. Build under network denial before considering any execution. ## Open ownership and authority

The original accepted-request/reply/destructor and hardware callbacks still need a fully reviewed all-client boundary. In particular the idle warm-up queue can outlive its load caller. The checked local slot/twin handoff is not a live-parent handle for queued producer work. Keep this producer uncovered until a bounded original handle can be acquired before queue publication, survive pickup, and be returned only after checked retirement or retained on refusal. A token copied after the original response is not a substitute.

The eager full warm-up must not return through the pre-transfer errdefers after resources moved to `LoadedModel`. Isolate the exact transfer point first: MTP-head allocation, late drafter-path duplication and hot-prefix storage can still fail after the first entry assignment in the current source. Bind CPU state and native fields to a single owner before first publication; distinguish pre-transfer failure, successful local publication and post-transfer held/refused outcomes. Update both callers (`runtime/loop.zig` primary startup and `runtime/load_requests.zig` queued load) so only the original claim can publish readiness or account resources. A post-transfer refusal must keep the original model, heap twin, slots and reservation; it must not drain the GPU, clear a latch, free pre-parsed CPU state, or rerun warmup. Require model-free controls at each boundary before deploying a new path. The scratch eager return is intentionally not shipped.

Continue to distinguish local release, explicit refusal, and unavailable authority. No fixture opts into Studio inference, installation, protected enrollment, or deployment. See [validation](validation.md) for exact receipts, failures, and continuation.
