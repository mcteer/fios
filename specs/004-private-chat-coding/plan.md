# Implementation plan · First private chat and coding

Deliver [T007](../001-platform-foundation/tasks.md#following-milestones) in three independently verifiable slices. The first usable release combines Mini chat with the promotion gate for its profile. The Studio can follow on its own schedule. [Specification](spec.md) · [Candidate research](research.md) · [Interfaces](contracts/chat.md)

## Technical context and source layout

Retain the Python standard-library control plane, Mini-local SQLite, OrbStack UI and native macOS workers. Place UI and browser assets under `src/frontend`, routing, authorization, storage and scheduling in `src/backend`, and the inference adapter, prompts, title logic and versioned publication policy in `src/agent`. MLX and the approved model runtime belong in an isolated native environment. Portable CI uses a deterministic fake runtime and fake time. Set hard limits before allocating workers, memory, disk or socket buffers.

## Control plane and storage

1. Add an opt-in real inference mode. Preserve Spec 3's loopback-only synthetic mode and fixtures. The Mini worker uses a private OS-peer-checked local channel with its own session, generation and advancing native capacity measurements. Studio workers keep their outbound enrolled mTLS channel. Both obtain an exclusive scheduler grant before loading or beginning work. Validate the job, lease, epoch, session, slot and pinned profile on payload access, output and settlement. Only local profile configuration chooses a runtime or path.
2. Stage a v1-to-v2 job database migration offline under the existing service lock. Rebuild the constrained holds table to cover the Mini, retain old jobs/receipts, and keep old fake profile definitions and historical prices. Real profiles use measured peak demand at the chosen cap, current pressure and fresh headroom. A conservative initial rule reserves the full qualified peak even for warm weights. Exercise exact-fit and one-byte-short cases. Retain one active job per executor, idle unload and cleanup proof. Keep synthetic global restore behavior compatible. In real mode create a durable hold for every potentially active executor on restore, including previously registered slots missing from the snapshot and the Mini. Quarantine all three possible slots independently. Each becomes eligible only after its own new session proves quiescence and reports fresh capacity. Studio absence cannot block a reconciled Mini.
3. Create a private content database beside the job database, both mode 0600 in a 0700 directory on the same local filesystem. Use an attached SQLite database with rollback journaling on both, full synchronization and a single connection/transaction for submission, deletion, publication and turn/job linkage. Keep prompt bytes and titles outside scheduler events, backups and metrics. Keep the existing offline job backup/restore limited to the scheduling database. Preserve current content on restore, reconcile orphaned turns to interrupted/unknown, and never recreate content for a deleted turn. Completed local history survives ordinary restart. Protect the content file as private operator data, document its separate backup scope and the data loss from loss of that file. [SQLite attached-database atomicity](https://www.sqlite.org/lang_attach.html)
4. Scope idempotency by owner, incarnation and original client key. Bind the immutable request to conversation, parent turn/version, requested alias, input, inventory option and caps. Store a private keyed digest for equality without retaining cleared text. Resolve retries before comparing current parent version or selecting the current alias revision. Commit at most one active turn per conversation. In the same immediate write transaction, count retained content and outstanding per-owner reservations. Charge stored prompt bytes immediately and reserve the worst-case answer and title growth before creating the job. Convert reserved bytes to retained bytes as content commits. Release the unused remainder exactly once on terminal settlement or deletion. Fence publication before releasing bytes, and reconcile interrupted turns and reservations together on restart or restore. A clear transaction tombstones the conversation, revokes grants/publication, removes active content including titles and queued input, and initiates cleanup. Late frames cannot recreate it. Quota or storage failure refuses new work. Terminal usage can still settle once.
5. Use an owner-only local history list, deterministic stable pagination, reopen and explicit deletion with the selected title shown for confirmation. Generate an initial subject title from the first approved exchange and refresh it on later completed turns when the subject changes. Extract specific subject words from the prompt and approved reply, exclude markup, private inventory fields and reasoning, cap the length, then apply title publication checks. An empty or withheld exchange retains a neutral placeholder. No model call or remote naming service is needed.

## Streaming, UI and policy

Replace the serial UI request handling with bounded concurrency and reserved capacity for Stop and health. Use same-origin streaming fetch, incremental UTF-8 decoding, accessible status updates and text-node rendering. Keep the existing inventory authorization and read-only observation mount. The UI container is independently deployable. Its only native mounts are read-only observations and a dedicated read-only bridge key. The native storage service owns SQLite and has its own lifecycle. A UI image replacement reuses the versioned chat API and does not open, copy, or migrate a database. Native workers and runtimes run in their own processes. The native loopback chat bridge checks that capability on every call and derives the bootstrap principal internally. Keep the operator socket, agent keys and data files outside the container. Origin, Host, content type, CSRF proof, and scoped action/ownership checks protect browser writes. Scope CSP script/connect to same origin for chat.

Use bounded chunks on separate data routes. Keep control-plane heartbeat, renew and cancellation capacity available during streaming. The Mini assembles context from approved prior turns in this conversation, current prompt and optional role-checked inventory. Tokenize the complete rendered template with the pinned tokenizer plus reserved output before dispatch. Drop oldest complete exchanges first, tell the user when context was shortened and reject a latest turn that cannot fit. Include only whitelisted timestamps, state and measurements when inventory is selected.

Version a local text policy with explicit allow/withhold/indeterminate decisions. Screen the assembled input before dispatch. At egress, accept only answer-channel text from the assigned runtime. Discard reasoning, tool calls and raw errors. Stage complete semantic segments under a hard cap. Check cumulative context plus held text before releasing a segment. If deciding depends on future context, hold through end of answer. Sensitive input/output uses full-answer review before releasing any text. Policy failure stops release, including history, derived title, and reconnect reads. Persist a checksum, verdict, policy revision and provenance atomically with each approved immutable segment. Prior segments on a stopped turn remain visibly partial and excluded from future context. Buffer limits or a lost active stream cause fenced cancellation. Every read revalidates current policy and owner. Record release delay separately from native TTFT.

## Qualification, rollout and recovery

First-time qualification uses a fixture-only admin grant with its own configured byte budget and minimum remaining headroom. Reserve the full trial budget on one exclusive slot before starting the cold runtime. Require fresh headroom of at least the budget plus the configured host floor and normal pressure at grant and immediately before launch. Record how the operator set both values for the host. Keep the Mini trial budget at or below its product ceiling. Ordinary admission continues to require measured evidence.

Use a native watchdog that operates independently of inference and covers loading, prefill, decode and cleanup. Record the sample interval and stale-data deadline ahead of the trial. Cancel on an observed trial footprint at or above budget, headroom below the floor, non-normal pressure, missing or stale measurements, preview health failure or trial deadline. Terminate and reap the trial-owned processes if cooperative stop fails within its bounded grace period. Sampling is a stop signal. Qualify the peak separately with high-water evidence and fail any trial that crossed its budget between samples. Keep the slot fenced until verified quiescence and fresh capacity. An aborted trial records a failure and leaves the candidate disabled.

Freeze model, tokenizer/template, runtime, OS/hardware class, settings, policy, eval set and rubric before trials. Keep a small tuning set and separate untouched holdouts. Test a two-turn Mini chat, factual inventory, two single-Studio coding tasks with functional assertions, safe ordinary conversation/code and permitted mature fantasy, prohibited/ambiguous cases using benign descriptions, and split-boundary/late-denial/outage cases. Check generated solutions in a bounded test-only interpreter for predefined declarative queries over a synthetic read-only dataset. Deny extensions, writes, extra statements and unbounded queries. This fixture grants no general code execution. Freeze expected results independently of model output. Record all failures and refuse promotion after any mandatory failure. Operator sets acceptable latency bounds before the first measured run and records them with the evidence. Require all measured trials to pass those bounds. Qualification and admin promotion may be exercised with isolated test data before real admission.

Run the isolated acceptance sequence in [quickstart.md](quickstart.md). Compare dashboard health against a two-second request deadline during each run. Check startup, fresh capacity, lease loss, cancellation, peak memory and original preview health after teardown. Before any Studio build or installation, record successful Mini-native agent recovery and two synthetic workers. Live coding requires approved Spec 2 enrollment of the chosen Studio, allowlisted private transport, artifact provenance and a passing trial there. The second Studio and RDMA are outside the release gate. A real alias begins disabled. Withdraw it, cancel active jobs, fence and release each executor after verified cleanup. Re-enable an independently qualified prior profile only when its evidence is still applicable. For a schema rollback, drain and take an offline backup before migration, retain conversation storage, and restore through the fenced recovery path with history reconciliation before serving. Never start old software against the new schema.

## Threat review and constitution check

| Boundary or failure | Required evidence |
| --- | --- |
| Browser submits arbitrary input as a local admin | Foreign origin, absent CSRF proof, forged role/owner, stale capability or content type denied. No browser path reaches host controls. Cross-owner resources remain undisclosed. |
| Model or remote worker supplies HTML, tool calls, secrets, arbitrary URLs or late frames | Literal rendering, fixed text-only adapter, grant-bound transfers, current policy before release, zero side effects, credential-free inference. Explicit loopback bind for native servers and fixed authorized endpoints. |
| Retry, restore, slow consumer or crash leaves partial output or duplicate work | Immutable turn/job link and key, independent slot quarantine, bounded buffering, private draft on crash, scoped cancellation and a fresh capacity challenge. |
| Changed model, host or policy invalidates evidence | Disable affected alias on any mismatch and fail closed on stale or missing measurements. Keep the other qualified alias independent. |

Pre- and post-design checks against the constitution pass at planning time. Only the control plane grants authority. Capacity requires fresh observations, private serving has explicit denial and recovery tests, real Studio work follows Mini qualification, and teardown targets only run-owned resources.
