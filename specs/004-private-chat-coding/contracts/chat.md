# Private chat interfaces

## Browser to container

The bootstrap listener accepts the existing exact loopback Host and peer rules. Use a per-browser unpredictable CSRF token bound to a same-site local session. JSON writes require exactly one matching Origin, a matching proof header and the expected media type. Reject supplied identity, unknown fields and unsupported bearer credentials. Keep GET side-effect free. The native chat bridge accepts only the chat capability, validates allowed operations and object ownership, and derives the actor. A future verified user may operate their own chats. Inventory attachment requires independent inventory-read authority. Promotion/withdrawal stays on the private admin socket.

| Operation | Observable contract |
| --- | --- |
| GET chat catalog and context | Return ledger incarnation, alias, active revision and availability reason. Omit keys, paths, grants and raw runtime URLs. |
| POST create conversation / GET history and conversation | Create an owned ID idempotently. List by descending last activity and ID with an opaque cursor, at most 50 per page. Return approved title, bounded turns and status for that owner. Use the same unavailable response for foreign and unknown IDs. |
| POST turn | Supply original incarnation, client key, conversation ID, expected parent, alias, plain UTF-8 prompt and inventory flag. Atomically enforce the owner quota and reserve answer and title bytes together with the new turn and job. Return a stable turn and job handle after commit. Return the original receipt on an identical retry without a second reservation, conflict on changed intent, stale parent or incarnation, and a typed unavailable/quota/too-large reason when appropriate. |
| GET turn stream | Return newline-delimited events with a monotone connection sequence and turn ID. State events report revision and recorded usage. Approved text carries a stable, one-based publication cursor. Pass the last cursor as `after` to resume the existing result without replaying that text or submitting new work. Limit one generation attachment per turn. |
| POST stop / delete | Stop is idempotent and acknowledges once no later publication can commit. UI discards in-flight text after acknowledgment. Deletion removes content, history entry and title, fences active work, and releases content and reserved quota in the same transaction. Executor cleanup remains independent. Confirm deletion of the specific conversation in the UI. |

Allocate time for the browser to attach after submission. If no stream opens within 15 seconds of submission, or the generation attachment disconnects, fence the turn. A lost or slow reader can retrieve approved history and terminal status. Teach the UI to distinguish transport loss from confirmed stop. Keep cancellation and health responsive within two seconds in isolated acceptance. Impose a five-second write deadline per stalled reader, bounded active connections, incremental UTF-8/frame parsing and no-store responses.

## Native service and executor

Use the Spec 3 start barrier, lease and cleanup challenge. Add a narrow grant-scoped request for prompt pages and a sequenced result append operation. For a Studio, both are worker-initiated over its authenticated channel. A local worker has the same typed operations via the OS-peer-checked Mini channel. Authorize each frame at commit. Fetch by job and grant only, once start is authorized. Keep data frames within 4 KiB of serialized content per message, with a server-issued cursor for prompt continuation. Split UTF-8 safely, reject gaps and excess bytes, and deduplicate exact frame retries by sequence and digest. Keep control-plane limits and reserve independent budget for payload traffic. Never dispatch a URI or use automatic provider fallback. Late data, malformed framing, reasoning-only output or missing final completion cannot produce a successful answer.

Use a fixed local runtime address and staged local weights. Explicitly bind to loopback, disable ambient credentials, unreviewed code, remote media and runtime network fetches. Whitelist template controls, output cap and text messages. Parse only recognized answer deltas. Support upstream usage-only chunks, keepalives and a single terminal marker. Enforce byte, token and elapsed-time limits while reading. Keep prompt caches owner-scoped or disabled. Cancel upstream and verify quiescence before releasing a hold. If quiescence cannot be verified, terminate and reap the owned process and require a fresh capacity sample. Keep recovery within the active reservation and honor maintenance stops. Dependency restart policy for OrbStack and other host services belongs to operations T009.

## Administration and privacy

Inspect profiles and evidence, promote or withdraw via typed admin operations. Require expected active revision for a change, recheck profile/target/evidence on admission, and reject stale promotion decisions. An isolated qualification grant can execute only the pinned fixture suite on a candidate with an exclusive trial reservation. The grant binds the candidate, slot, fixture suite, trial budget, headroom floor and deadline. Admission requires fresh normal-pressure capacity covering the budget and floor. On a budget breach, unsafe pressure or missing measurements, report failure, fence the trial, and retain the slot until stop and cleanup are verified. Use trial results as promotion evidence only after all gates pass. Record reason codes, elapsed time, revision, token tags and policy version in operational records. Keep content, title, detector input, capability, lease and raw model diagnostics private. Publication decisions bind to the specific output checksum and policy version across stream, title and history.


## Local text-policy service

The native control plane posts `purpose`, `text`, and the exact 64-hex-digit policy `revision` to its configured loopback `/v1/classify` endpoint. Purposes are input, answer, and title. A successful response echoes `X-Fios-Policy-Revision` and returns one bounded boolean decision. Revision mismatch, malformed decisions, timeout, or unavailable service withhold the content. The checker evaluates the full serialized transcript and answer with its own 4,096-input-token limit. When a conversation exceeds that limit, it withholds the turn. The Studio runtime context benchmark measures native inference independently of this gate. Qualify both permitted and prohibited fixtures before using a real policy revision.
