# Qualification and recovery guide

Use this procedure for isolated qualification. The [task record](tasks.md) lists measured results and open gates.

1. **Portable suite.** Run the existing `make check`, then the planned `make chat-test`. Use temporary job and content databases, a controlled clock and fake streams. Check migration from a populated Spec 3 ledger, deletion, replay, stale grants, cancellation, classifier failure, full quotas, concurrent turns across two conversations sharing one owner quota, escaped HTML and independent restore. Repeat concurrent submission, finalization, withdrawal and deletion races 100 times. Race two valid requests with room for one. Confirm one quota refusal, a duplicate receipt with no extra charge, and reuse of released bytes after settlement or deletion. Restart with a pending reservation and verify reconciliation. Keep the current synthetic scheduling tests green.
2. **Mini rehearsal.** Run the planned `make chat-acceptance` on fios-core. Use unique loopback ports, test credentials, launchd labels and a disposable Compose project. Record original preview health and resource inventory. Start the local native agent and two synthetic Studio workers. Verify advancing telemetry, restart and recovery, and simulate both Studios offline. With an active stream, Stop and health should each respond within two seconds. Repeat with a stalled reader and lost native process. Test keyboard-only compose, stop, reopen and delete in a real browser at narrow and desktop widths. Confirm the CSS and CSP permit the intended controls.
3. **History and publication.** Use three distinct held-out topics with predefined subject terms. After their first successful turns, verify distinct subject-bearing titles, revisit after restarting, and continue with a follow-up using earlier context. Delete one during generation and replay old data and receipts. Its title and turns must remain inaccessible, the other two unchanged, and the ledger must retain only redacted accounting. Inspect UI, API, titles, reconnect and stored diagnostics with unique private markers. Include release decisions whose classification changes across chunk boundaries.
4. **Mini qualification.** With approved local model/runtime artifacts, record hashes, license, OS, tokenizer/template, settings, policy, quotas and latency budgets before running. A dedicated downloader may use an operator-provisioned credential during acquisition only. Before starting an unmeasured candidate, record the trial budget, host headroom floor, watchdog sampling interval, stale-data deadline and stop grace period. Rehearse exact-fit and insufficient headroom, then inject excess footprint, pressure and missing measurements into a disposable trial. Verify refusal or abort as applicable, disabled alias, fenced slot and fresh capacity after cleanup. At each supported total context size, measure cold start and working peak on a fixed prompt. At the highest passing size run one cold and at least five warm trials. Record individual TTFT, first approved text, decode tokens/s, footprint, pressure, preview health and cancel-to-idle. Exercise two turns and inventory ground truth. A working set at or above 6,000,000,000 bytes, pressure above normal, missing cleanup evidence, failed holdout or missed latency bound blocks activation. Use a held-out policy set with approved mature and innocuous boundary examples and require zero critical escapes or false denials of mandatory allowed controls. Withhold approval if the checker or evidence is unavailable.
5. **Studio qualification.** After documented Mini rehearsal and approval/enrollment of the first Studio under [Spec 2 T022](../002-studio-enrollment/tasks.md#phase-6--qualification-cleanup-and-gated-rollout), stage only the reviewed runtime and model there. Confirm local-only listening and the authenticated outbound worker path. Set the Studio's trial budget and headroom floor from its own capacity and apply the same abort checks. Reuse the same cold/warm procedure at the chosen context and record actual peak and fresh headroom. Use two frozen coding tasks with functional checks, inspect answer/reasoning split, disconnect and cancel mid-decode, kill the owned runtime and prove cleanup before slot reuse. Check Mini chat and dashboard during Studio loss. Require trustworthy measurements and operator acceptance before promotion.
6. **Rollback and cleanup.** Withdraw one alias while work is queued and running. Verify admission closes, stale chunks are denied, cleanup completes and the other alias works. Test a prior qualified revision and snapshot restore on disposable data. Test normal exit and interrupt cleanup. Remove only recorded run-owned processes, credentials, state, containers, image tags and staged trial files, preserving operator-retained artifacts. Verify the original preview still responds and record the evidence and outstanding hardware gates in tasks.md.


## Record a qualified revision

The portable entry points are `make check`, `make scheduling-test` and `make chat-test`. On the Mini, `make chat-acceptance` checks WebKit and the isolated OrbStack container. With reviewed local weights and a pinned Python environment staged in a private trial directory, `tests/macos/prepare_mini_trial.py` writes the attested runtime, policy and browser configurations. Set `FIOS_CHAT_NATIVE_TRIAL_CONFIG` and `FIOS_CHAT_NATIVE_POLICY_CONFIG` to those JSON files, `FIOS_CHAT_TRIAL_PROFILE` to the profile JSON contents, and `FIOS_CHAT_TRIAL_POLICY_REVISION` to the policy configuration's revision. The native browser check exercises the model and checker against a disposable catalog.

Run `tests/macos/qualify_mini.py` with the attested configuration, private state path, 6,000,000,000-byte ceiling, and the recorded host headroom floor. Set `--input-tokens 512 --output-tokens 512 --fill-context` for the evaluated Mini profile. On the approved Studio, `tests/macos/verify_studio_hardware.py` takes the SSH host, private staging root, Mini's LAN bind address and native policy configuration. The staging root must contain the pinned runtime environment and the verified model file manifest. The temporary CA and listeners close when the trial ends. The operator owns cleanup of the explicitly staged model and environment.

Use the native operator socket for `model-status`, `model-trial REVISION SLOT`, `model-record REPORT.json`, `model-promote ALIAS REVISION`, and `model-withdraw ALIAS --expected REVISION`. For a replacement or rollback, include the currently promoted revision with `--expected`. Run through the native `backend.enroll` CLI. A report has a validated profile and evidence tied to that profile. Real evidence names the slot, measured peak bytes, artifact/runtime/policy/evaluation digests, host build, cold and warm trial counts, latency bound and worst observed latency, and a result for quality, publication, context, cancellation, cleanup, license and rollback. Record failed real trials with the failed checks. The test ledger accepts separate synthetic trial evidence for fixture execution. Production promotion reads real evidence only.

Withhold activation if a required test fails. A model withdrawal leaves approved conversation history available under the separately pinned policy revision. A restore clears activated aliases and preserves conversation content subject to that policy.
