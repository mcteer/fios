# Validation and rollout guide

Use this guide during implementation. The new Make targets below are deliverables of this feature. `make check` already exists.

## Gate A · qualify on fios-core

1. From the project root on the Mini, confirm the selected feature and run the foundation baseline. Record revision, Python/SSL/SQLite/OpenSSL versions and OrbStack context. Verify the preview still answers `curl -fsS http://127.0.0.1:8741/healthz`.
2. Run `make enrollment-test`. The target creates a temporary signer, server identity, two distinct worker identities and denial fixtures. It initializes the private ledger via `python -m backend.enroll init --state-dir PATH`, using a new path under the run's private directory. It starts a loopback collector and operator socket with allocated test ports. It exercises fail-closed startup with a missing ledger and approved and denied actions through the CLI, real TLS clients and the dashboard API. Check first report within ten seconds, cross-slot isolation, the 30-second boundary, byte-for-byte preservation of last-good observations on rejected reports, and independent progress by the second worker.
3. Run `make enrollment-acceptance` on fios-core. Build/package the native Python service from this checkout. Use run-specific launchd labels, a separate OrbStack Compose project with unique container/image names and noncolliding loopback ports, and one private temporary directory. Exercise the built artifact with two synthetic identities and at least one real native host measurement. Verify dashboard health and both read-only views, fresh telemetry, service restart, worker exit/relaunch and connection recovery. Record original and replacement worker PIDs and time from restored authenticated connectivity to first accepted sample. Check core restart requires a new sample from each active worker. Record a harmless rejection reason and verify the other worker remains current during leaf rotation or revocation.
4. Rehearse planned root rollover. Independently verify and install the new public root alongside the old on the worker and core. Reload trust stores, verify new server identity, then rotate each worker to its replacement leaf. Remove the old root on both sides, reload, invalidate old sessions and test both directions with old-only credentials. For failure before retirement, stop rollout with only known-good, uncompromised trust; after retirement, recover forward with new credentials. Exercise the compromise cutoff separately.
5. Run `make check`. Capture the revision or build digest, test results, timing and resource cleanup in the evidence section of [tasks](tasks.md). Teardown must run on interruption too. Remove only this run's jobs, temporary PKI, database, build outputs, containers and image tags. Verify the original preview and sampler are healthy, unrelated resources survived and no test job or tag remains. Keep sanitized evidence outside disposable paths.

Gate A passes only with recorded results for startup, health, telemetry, supervision, recovery, both synthetic workers, and clean teardown. Linux CI can provide portable contract evidence. Native macOS and OrbStack evidence must come from the Mini.

## Gate B · one approved Studio at a time

Before any build or installation on either Studio, obtain passing Gate A evidence and operator approval of the actual machines, stable slot mappings, private listener address, core SAN, worker SANs and trust anchor fingerprint over an independent channel. Confirm live deployment authorization and the unprivileged service identities. Use the same qualified, digest-verified revision or artifact. Keep private keys on their respective hosts. An existing SSH login is a transport convenience.

Install the worker as a system LaunchDaemon with an explicit unprivileged UserName, service-owned mode-0600 key in a private directory, absolute read-only executable paths, KeepAlive and bounded logs. Validate its plist with `plutil -lint`, inspect the approved job with `launchctl print system/local.fios.worker`, and verify a native sample advances twice under its approved slot. Confirm the dashboard still answers locally and the worker listener exposes no UI/admin route. Record the result for `edge-a` before repeating for `edge-b`.

Stop on unexpected identity, slow recovery, lost Mini access or a failed isolation check. Revoke the affected binding through the local CLI, verify denial and remove only that worker's job and run-owned installation. Leave the other worker and dashboard available. Restore the previously qualified service revision only if it enforces the current trust ledger. Re-enrollment needs a new leaf and explicit approval. Record per-host results separately, including any pending host.
