# Research decisions for Studio enrollment

| Decision | Reason and alternatives considered |
| --- | --- |
| Run one native enrollment service on the Mini. Keep the existing dashboard in OrbStack. | macOS can bind the worker listener to the approved management address. The dashboard can read a narrow, read-only native endpoint over shared loopback. Putting both listeners in the container would give the UI service access to worker credentials. Publishing per-worker JSON files would need a separate way to invalidate cached trust immediately after revocation or service failure. [OrbStack host networking](https://docs.orbstack.dev/docker/host-networking) |
| Use TLS 1.3 with an operator-approved private CA bundle, both peers presenting leaves, and a full-leaf SHA-256 pin per worker. | TLS authenticates the peers. The pin lets the operator authorize and retire an individual certificate within a trusted chain. Checking a hostname or CA membership alone would grant too many machines the right to report. Use explicit trust stores, DNS/IP SAN verification and distinct client/server usages. [Python SSL contexts](https://docs.python.org/3.11/library/ssl.html) · [OpenSSL certificate profiles](https://docs.openssl.org/3.5/man5/x509v3_config/) |
| Keep issuance offline. Generate private leaf keys on the consuming host, use an approved signing profile, and manually approve the machine-to-leaf binding. Proposed defaults are 30-day leaves and a one-year private root. | Two workers can rotate individually. An online CA, automated discovery and a secret in SSH or the environment would enlarge the trust boundary. Owner-only native key files permit unattended startup with the existing Python runtime. Operator protection of the signer and the host filesystem is a deployment prerequisite. [OpenSSL CA guidance](https://docs.openssl.org/3.5/man1/openssl-ca/) |
| Use a single native writer and SQLite transactions for bindings, retired pins and administrative audit. Keep accepted observations and sessions in memory. | A crash must retain withdrawals of trust and require a new heartbeat. A shared database mount would give the UI a view of private enrollment data. A DB server would add a service for two slots. Short local transactions serialize durable changes. [SQLite transactions](https://www.sqlite.org/lang_transaction.html) |
| Run the worker as a foreground launchd job, with immediate sampling on connection and five-second sampling thereafter. | A boot-time LaunchDaemon under a dedicated unprivileged user supports unattended Studio recovery. A login agent suffices to test restart behavior on the Mini but requires a login. Handle transient network errors inside the worker to avoid launchd crash throttling. [Apple launchd guide](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html) |
| Give each reconnect a core-issued session ID. Use source wall time to bound age and core elapsed time to age an accepted sample. | A sequence alone repeats after restart. A receipt-only clock could make an old sample fresh for another 30 seconds. The selected bounds and replay rules are specified in the [data model](data-model.md). |

These are design choices for qualification. The operator supplies the real management addresses, certificate identities and trust anchor before live enrollment. Neither measured recovery times nor Studio compatibility have been established by this research.
