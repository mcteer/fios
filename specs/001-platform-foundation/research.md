## Inference backends and the Studio pair

“mlx-server” names several projects. Use an internal model alias and a small OpenAI-compatible adapter. The baseline here means upstream `mlx_lm.server`. A separate Swift mlx-server and the Zig-based MLX-Serve are distinct options. No binary is selected from a name match alone. [MLX-LM server](https://github.com/ml-explore/mlx-lm/blob/main/mlx_lm/SERVER.md) · [Swift mlx-server](https://github.com/defilantech/mlx-server) · [MLX-Serve](https://github.com/ddalcu/mlx-serve)

**Benchmark protocol.** Record host/OS, runtime commit, artifact bytes/digest, precision, rank count, actual transport, prompt length, output cap, batch size, peak resident/Metal memory, TTFT and steady decode tokens/s. Avoid adding overlapping RSS and Metal totals. Use identical prompts with fixed decode settings. Compare one Studio, two independent replicas under two clients, and a single two-rank job. Run a cold start then at least five warm requests per configuration, report individual observations and median, and measure the capacity lost to other work. Repeat at short and long context and test cancellation, a rank exiting and link loss. Distributed mode earns a catalog entry when it fits an otherwise inadmissible model or demonstrates a measured service benefit. Neither the 512 GB aggregate nor link bandwidth is a usable single-host allocation.

## Operations and containment

Native agents fit macOS service supervision via launchd. Start under an unprivileged identity with explicit paths, restart throttling and dedicated state. Keep privileged OS maintenance separate. Use reported runtime memory plus node pressure and actual leases to schedule. For telemetry, track input/output token counts, duration and first-token delay with bounded dimensions and a pinned semantic-convention version. Deduplicate usage and distinguish local electricity estimates from paid provider charges. [Apple launchd guide](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html) · [OpenTelemetry GenAI metrics](https://opentelemetry.io/docs/specs/semconv/gen-ai/gen-ai-metrics/)

OrbStack supports localhost sharing via host networking. Ordinary port publishing and container domains offer other ingress paths. The foundation listens on loopback and trusts the dedicated Mini's local processes. Run experiments with generated code on the Studios under a separate executor identity. Docker's daemon is privileged, containers share a kernel and default resource limits need explicit configuration. Isolated OrbStack Linux machines remove host integrations, but their network policy and shared kernel need evaluation. Apple's per-container lightweight VMs offer a separate isolation candidate. For hostile or multi-user code, prefer a disposable dedicated guest with explicit egress denial and no shared host directories. Validate settings on the installed version before enabling UI jobs. [OrbStack host networking](https://docs.orbstack.dev/docker/host-networking) · [OrbStack isolated machines](https://docs.orbstack.dev/machines/isolated) · [Docker security](https://docs.docker.com/engine/security/) · [Resource limits](https://docs.docker.com/engine/containers/resource_constraints/) · [Apple container](https://github.com/apple/container)

## Projects, search and creative work

SQLite WAL fits a single core writer and concurrent local readers. Put the DB on a local managed volume, use SQLite's backup API during live operation and verify artifact consistency on restore. Scope retrieval and exports to owner and audience. Begin with a summary plus selected canon and source references. Avoid retaining sensitive prompts in telemetry. [SQLite WAL](https://www.sqlite.org/wal.html) · [SQLite backup API](https://www.sqlite.org/backup.html)

SearXNG supports JSON search when the instance explicitly enables that format. A self-managed instance still sends queries to configured engines. A managed search API remains an alternative if the operator approves the data flow and price. Neither route requires arbitrary URL fetching by the model. Verify citation freshness, source quality, deadlines, privacy and SSRF protection with fixtures before a live query. [SearXNG Search API](https://docs.searxng.org/dev/search_api.html) · [OWASP SSRF prevention](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)

For campaign planning, track open situations, the cast, clues and what changes if nobody intervenes. Prepare enough alternatives for player agency. For one-shots, budget time for the ending and mark optional scenes. Version player-facing handouts separately from GM notes. Use original visual descriptions and allow the table to override stylistic traits. For imported rules use licensed SRD material, preserve its edition and required attribution. Homebrew and licensed canon need separate provenance. [Sly Flourish prep method](https://slyflourish.com/eight_steps_2023.html) · [Wizards SRD and license](https://www.dndbeyond.com/srd)

Use a distinct policy decision for mature violence, substance use, clearly adult nudity and sexual depictions involving minors. A single generic NSFW score cannot implement those decisions. Evaluate false positives on allowed adult and short-stature fantasy characters and fail closed on uncertain sexualized youth. Route every result, including model previews and caches, through publication controls. US law includes distinct provisions concerning depictions of minors. The platform adopts a categorical ban on sexual depictions involving minors regardless of visual medium. Legal coverage for public hosting and incident handling is a later review. [18 USC §2256](https://uscode.house.gov/us/usc/t18/s2256/) · [18 USC §1466A](https://uscode.house.gov/view.xhtml?req=granuleid:USC-prelim-title18-section1466A&num=0&edition=prelim)

For public identity, Google documents the OIDC discovery endpoints, issuer/audience checks and ID token validation. Bind users by issuer and subject and map administrative membership separately. Issue high-entropy API keys with scopes, hashed storage, expiry, rotation and revocation. Test ownership migration from the single bootstrap principal and keep service-to-service credentials independent. [Google OpenID Connect](https://developers.google.com/identity/openid-connect/openid-connect) · [OAuth security best current practice](https://www.rfc-editor.org/rfc/rfc9700)

## Spec 1 design decisions

- Use a native sampler for the Mini so physical memory and load refer to macOS. Container-local sampling would measure the guest environment.
- Atomically replace a bounded local file per host. The reader needs only the latest observation, and a read-only mount avoids introducing network enrollment before machine identity is available.
- Serve HTML and the inventory read from one loopback origin. A separate frontend origin would introduce another trust boundary for the same read-only workflow.
- Keep the pinned developer tools outside the dashboard image so a developer can reproduce the Spec Kit workflow independently of the application runtime.
